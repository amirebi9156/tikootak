# گزارش ممیزی امنیتی TIKOOTAK (طبق رودمپ ۷ فازی)

نسخهٔ بررسی‌شده: tikootak-UI22 · تاریخ: 2026-10-24
روش: خواندن کد gateway/scripts/Caddy/compose + تست خودکار روی نسخهٔ لوکال (Synapse + gateway + LiveKit + مرورگر).
**محدودیت صادقانه:** این بررسی توسط همان هوش مصنوعی‌ای انجام شد که کد را نوشته؛ مستقل نیست. Docker و Caddy اینجا اجرا نشد، پس بخش‌های زیرساخت فقط «از روی کد» بررسی شدند (🟡). پیشنهاد: بعد از انتقال به سرور، یک بار هم با ابزار مستقل (مثلاً OWASP ZAP/`nmap`) اسکن بشود.

راهنما: ✅ امن بود · 🔧 مشکل داشت و رفع شد · 🟡 روی سرور واقعی باید تأیید شود · ℹ️ ریسک آگاهانه/باقی‌مانده

## خلاصهٔ اجرایی
- **۲۴ بند بررسی شد: ۱۳ ✅ (امن از ابتدا) · ۹ 🔧 (مشکل داشت و رفع شد؛ ۱ مورد‌شان هنوز 🟡 روی سرور تأیید شود) · ۲ 🟡 (فقط روی سرور قابل‌تأیید)**
- **بحرانی (🔴) پیدا نشد.** مشکلات واقعی: ۱) EXIF/GPS عکس و ویدیو پاک نمی‌شد (نشت حریم خصوصی) ۲) نوع فایل فقط از هدر خوانده می‌شد ۳) ffmpeg بدون محدودیت پروتکل ۴) هدر امنیتی نبود ۵) gateway با root اجرا می‌شد ۶) بن با `admin.sh` در gateway اعمال نمی‌شد ۷) ادمین از همه IPها قابل‌دسترس بود.
- تست‌های خودکار جدید: `sec01` (۹) · `sec03` (۲۷) · `sec04` (۴) · `sec05` (۴) — همه پاس. تست‌های قدیمی تماس و ریاکشن (e2e2، e2e24) هم پاس.

## فاز ۱ — احراز هویت و نشست
| بند | وضعیت | یافته |
|---|---|---|
| ۱.۱ اعتبارسنجی توکن | 🔧 | توکن با `whoami` تأیید می‌شود. **کش مثبت ۶۰ ثانیه بود** (توکن خارج‌شده تا ۶۰ثانیه معتبر می‌ماند) → به ۲۰ ثانیه کم شد (`feed.js`). بن gateway فوری است (هر درخواست از DB چک می‌شود). قطع Synapse: پاسخ ۵۰۲ (fail-closed)؛ فقط توکن‌های کش‌شده تا ۲۰ث کار می‌کنند. |
| ۱.۲ رمزنگاری | ✅ | همهٔ کدها/کلیدها با `crypto.randomBytes`. `Math.random` فقط در تصادفی‌سازی رتبه‌بندی فید و پاک‌سازی لاگ (بی‌خطر). مقایسهٔ کلید ادمین و امضای مدیا با `timingSafeEqual`. |
| ۱.۳ Brute-force | 🔧 | Rate limit روی ثبت‌نام/ورود/ادمین/توکن تماس بود؛ `trust proxy=1` درست است (Caddy هدر `X-Forwarded-For` ورودی را بازنویسی می‌کند و gateway از بیرون در دسترس نیست). **اضافه شد:** قفل ۱۵دقیقه‌ای حساب بعد از ۱۰ تلاش ناموفق، سیاست رمز ≥۱۰ نویسه + رمز رایج، محدودیت ورود در Synapse (`policy.js`). فراموشی رمز وجود ندارد. |

## فاز ۲ — کنترل دسترسی / IDOR
| ۲.۱ IDOR | ✅ | ۲۷ آزمون خودکار (`sec03`): حذف پست/نظر/استوری/آهنگ/پلی‌لیست دیگران رد می‌شود (۴۰۳/۴۰۴)؛ اعلان‌ها و «خوانده‌شد» همه با `user_id` فیلتر می‌شوند. |
|---|---|---|
| ۲.۲ حریم خصوصی | ✅ | بلاک و مخاطب استوری در بک‌اند اعمال می‌شود (کاربر بلاک‌شده نمی‌تواند نظر بدهد/استوری ببیند/جستجو شود). |
| ۲.۳ لینک مدیا | ✅ | HMAC روی `id|user|expiry`؛ دستکاری امضا، کاربر و انقضا → ۴۰۳؛ path traversal → ۴۰۳. نام فایل فقط از DB می‌آید. |
| ۲.۴ ادمین | 🔧 | همهٔ مسیرهای `/api/admin/*` از `requireAdmin` رد می‌شوند (جستجو شد؛ مسیر بدون آن نیست). **اضافه شد:** فهرست سفید IP (`ADMIN_ALLOW_IPS`)، لاگ حسابرسی ۹۰روزه، چرخش کلید، هشدار کلید ضعیف. |

## فاز ۳ — تزریق
| ۳.۱ SQL | ✅ | همهٔ کوئری‌ها prepared هستند؛ تنها درون‌یابی رشته‌ای، نام جدول/ستون‌های ثابت داخل کد است (نه ورودی کاربر). جستجوها `ESCAPE` دارند. |
|---|---|---|
| ۳.۲ Command injection | ✅ | `spawn` با آرایهٔ آرگومان و بدون shell؛ نام فایل ورودی ffmpeg از شناسهٔ تصادفی خود سرور ساخته می‌شود. |
| ۳.۳ XSS | ✅ | React متن را escape می‌کند؛ هیچ `innerHTML`ی نیست؛ فقط لینک `http(s)://` فعال می‌شود؛ CSP جلوی اسکریپت inline را هم می‌گیرد. SVG آپلود مجاز نیست. |
| ۳.۴ Mass assignment | ✅ | `req.body` هرگز spread/merge نمی‌شود؛ فقط فیلدهای مشخص خوانده می‌شود. |

## فاز ۴ — آپلود و مدیا
| ۴.۱ Magic bytes | 🔧 | قبلاً فقط Content-Type چک می‌شد. حالا محتوای واقعی در همهٔ آپلودها چک می‌شود (`sniff.js`)؛ فایل جعلی → ۴۱۵. |
|---|---|---|
| ۴.۲ ffmpeg | 🔧 | تایم‌اوت ۱۸۰ث، یک worker، `nice 19`، یک thread بود. **اضافه شد:** `-protocol_whitelist file,pipe` (برای ffmpeg و ffprobe)، رد ابعاد بیش از ۴۰ مگاپیکسل (Pixel bomb). |
| ۴.۳ EXIF | 🔧 | **باگ واقعی حریم خصوصی:** GPS و مدل دستگاه در عکس‌ها (و ویدیوهای سبک که دوباره کدگذاری نمی‌شدند) می‌ماند. حالا JPEG/PNG/WebP پاک‌سازی می‌شود (جهت عکس حفظ می‌شود) و ویدیو همیشه با `-map_metadata -1` (یا remux بدون کدگذاری) پردازش می‌شود (`strip.js`، `transcode.js`). تست `sec05`. |
| ۴.۴ سرو امن | ✅ | همهٔ مسیرهای مدیا `nosniff` + `CSP: default-src 'none'; sandbox` دارند. `Content-Disposition: attachment` عمداً نیست (پخش درون‌برنامه‌ای لازم است) — ℹ️. |

## فاز ۵ — تماس و چت
| ۵.۱ توکن LiveKit | ✅ | قبل از صدور توکن عضویت در اتاق Matrix چک می‌شود؛ مجوزها فقط join/publish/subscribe (بدون admin/record)، اعتبار ۲ ساعت. |
|---|---|---|
| ۵.۲ TURN/WebRTC | 🟡 | TURN داخلی LiveKit فعال است. اینکه Relay به شبکهٔ داخلی (`10/8`، `172.16/12`، `192.168/16`، loopback) بسته است **در این محیط قابل‌اثبات نبود**. روی سرور: فایروال میزبان خروجی‌های داخلی را از کانتینر livekit ببندد (S5 `harden-host.sh`) یا با `nmap`/`turnutils_uclient` تست شود. |
| ۵.۳ همگام‌سازی بن/حذف | 🔧 | `admin.sh ban` فقط Synapse را غیرفعال می‌کرد و بن gateway ثبت نمی‌شد → حالا هر دو انجام می‌شود. حذف پست/استوری/آهنگ فایل فیزیکی را پاک می‌کند و لینک قبلی ۴۰۴ می‌شود. اخراج از اتاق‌های Matrix بعد از بن: 🟡 (غیرفعال‌سازی حساب جلوی ادامهٔ حضور را می‌گیرد؛ عضویت در اتاق باقی می‌ماند). |

## فاز ۶ — حریم خصوصی و نشت
| ۶.۱ خروجی API | ✅ | پاسخ‌های پروفایل/جستجو/فید/اعلان بررسی شد؛ فقط id، نام، آواتار، بایو و شمارنده‌ها. ایمیل/IP/توکن/کد دعوت فقط در API ادمین. |
|---|---|---|
| ۶.۲ خطاها | ✅ | هندلر خطا فقط JSON استاندارد برمی‌گرداند؛ stack فقط در لاگ سرور. |
| ۶.۳ لاگ و بکاپ | 🔧 | لاگ‌ها هدر Authorization/رمز را چاپ نمی‌کنند (✅). `backup.sh` پوشهٔ موقت را با `mktemp -d` (۷۰۰) می‌ساخت و فایل خروجی ۶۰۰ بود؛ `umask 077` هم اضافه شد. بکاپ شامل `.env` است → رمزگذاری بکاپ در مرحلهٔ S6 هست. |

## فاز ۷ — زیرساخت و DoS
| ۷.۱ Docker | 🔧🟡 | Postgres/Synapse/gateway هیچ پورتی به بیرون ندارند؛ فقط Caddy و LiveKit. سوکت docker مونت نشده ✅. اضافه شد: gateway غیر-root + `read_only` + `cap_drop: ALL` + `no-new-privileges` + سقف pids؛ بقیه `no-new-privileges`. **روی Docker واقعی اجرا نشده (🟡).** همهٔ سرویس‌ها روی یک شبکهٔ پیش‌فرض‌اند (ℹ️: تفکیک شبکه ارزش افزودهٔ کمی دارد). |
|---|---|---|
| ۷.۲ Caddy | 🟡 | هدرهای CSP/HSTS/X-Frame/nosniff/Referrer/Permissions اضافه شد (CSP با پروکسی تست و مرورگر امتحان شد، بدون نقض)؛ `/_synapse/admin/*` مسدود؛ ریشهٔ وب فقط `web/dist` است پس `.env`/`.git`/DB قابل‌سرو نیستند. **خود Caddy اجرا نشد** → `caddy validate` روی سرور. |
| ۷.۳ DoS | ✅ | `express.json` سقف ۱۰KB؛ `urlencoded` استفاده نمی‌شود؛ همهٔ لیست‌ها سقف دارند (فید ۳۰، اعلان ۵۰، نظر ۲۰۰، جستجو ۱۵، فالو ۲۰۰، آهنگ ۵۰۰). Regexهای پیچیده/ReDoS-پذیر وجود ندارد. |

## باقی‌مانده / توصیه‌ها
1. 🟡 روی سرور: `caddy validate`، تست `docker compose up` با `read_only`، `./scripts/doctor.sh`.
2. 🟡 تست TURN برای بسته بودن مسیر داخلی (بند ۵.۲) و فایروال میزبان (S5).
3. ℹ️ قفل حساب بعد از ۱۰ تلاش می‌تواند توسط مهاجم برای «قفل‌کردن عمدی» حساب دیگری استفاده شود (۱۵ دقیقه).
4. ℹ️ پیام‌های ناپدیدشونده فقط وقتی برنامهٔ فرستنده باز است از سرور پاک می‌شوند.
5. ℹ️ این ممیزی خودبررسی است؛ یک بازبینی مستقل یا اسکن خودکار (ZAP) توصیه می‌شود.
