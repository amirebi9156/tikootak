# Q6 — پیام‌های کانال به نام کانال

نسخهٔ ۰.۳۵.۸.

## نمایش پیام
- در `Chat.jsx` برای `roomKind === 'channel'`، حباب هر پیام با **آواتار و نام کانال** رندر می‌شود (`RoomAvatar` + `room.name`)، حتی برای پست admin خودِ بیننده.
- نام ادمین فرستنده در حالت عادی پنهان است. همهٔ پیام‌های کانال در سمت چپ (کلاس `theirs chan`) نمایش داده می‌شوند تا ظاهر کانال حفظ شود.
- ریپلای/کوت، کپی چندتایی، فوروارد و «ذخیره در پیام‌های ذخیره‌شده» هم نام کانال را می‌برند، نه نام ادمین.
- پیش‌نمایش لیست گفتگوها (`Shell.jsx` → `Preview`) برای کانال `«نام کانال»: متن` نشان می‌دهد؛ «تو:» و تیک خوانده‌شدن برای کانال حذف شده است.

## امضای پیام‌ها
- state event سفارشی: `ir.tikootak.channel_signing` با `{enabled: boolean}` (نام قدیمی `ir.tikotak.channel_signing` هم خوانده می‌شود).
- پیش‌فرض **خاموش**؛ فقط admin/owner (power ≥ 50) می‌تواند از `RoomSettings` تغییرش دهد.
- وقتی روشن باشد، نام ادمین فرستنده کوچک زیر هر پست (`channel-sign`) نمایش داده می‌شود.
- برای **پست‌های قدیمی** هم مقدار فعلی state event اعمال می‌شود؛ هیچ داده‌ای به پیام‌های قبلی اضافه نمی‌شود.
- state eventها در Matrix رمزنگاری نمی‌شوند؛ فقط یک boolean است و متن پیام/E2EE دست‌نخورده می‌ماند. برای اتاق رمزنگاری‌شده و رمزنگاری‌نشده یکسان کار می‌کند.

## اعضا و دعوت‌کننده
- `RoomSettings` برای کانال، لیست اعضا و دعوت‌شده‌ها را فقط به `mod` (admin/owner) نشان می‌دهد؛ عضو عادی پیام «لیست اعضای کانال فقط برای مدیران است» می‌بیند.
- برای گروه/کانال، «دعوت‌شده توسط …» فقط برای admin نمایش داده می‌شود (member event sender)؛ عضو عادی نمی‌بیند.
- دیالوگ اعضای `Chat` هم برای کانال فقط با power ≥ 50 باز می‌شود.

> این محدودیت در لایهٔ UI است. در Matrix، state eventهای عضویت برای اعضای اتاق قابل خواندن‌اند؛ پنهان‌کردن کامل در سطح پروتکل بدون تغییر معماری/سرور ممکن نیست.

## تست
- `tests/ui/channel-signing.test.mjs` — پیش‌فرض خاموش، روشن‌شدن با state event جدید و نام قدیمی.
- Playwright واقعی (admin پست می‌گذارد، عضو عادی نام کانال/نبود نام ادمین و مخفی‌بودن لیست اعضا را می‌بیند) در این محیط اجرا نشد؛ نیاز به Matrix زنده و مرورگر دارد.
