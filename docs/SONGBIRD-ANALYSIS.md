# بررسی پروژهٔ Songbird و آنچه برای TIKOOTAK برداشتیم

منبع: https://github.com/bllackbull/Songbird (نسخهٔ 0.13.1، MIT، ~۵۲۰ کامیت). فقط **ایده‌ها** را برداشتیم؛ کدی کپی نشده.
Songbird یک چت Node/Express + React است (چت خصوصی/گروه/کانال، تماس WebRTC، پنل ادمین). ما Matrix/Synapse + LiveKit + ریلز/موزیک/استوری داریم؛ پس «نصب آسان» و «مدیریت بعد از نصب» را از آن‌ها یاد می‌گیریم، نه معماری را.

## «نصب آسان» در Songbird دقیقاً یعنی چه؟
۱. یک دستور: `curl … /scripts/install.sh | bash` که یک **منوی تعاملی** باز می‌کند و خودش را به‌صورت فرمان سراسری `songbird-deploy` نصب می‌کند.
۲. همهٔ چرخهٔ عمر در همان منو است: نصب، آپدیت/دانگرید، ریستارت، ویرایش تنظیمات، مدیریت دیتابیس، حذف، لاگ‌ها، آینه‌ها، آپدیت خود منو.
۳. نصب سؤال‌به‌سؤال (دامنه/IP، نوع گواهی، SQLite/Postgres، پورت‌ها) و رمزها/کلیدها را **خودکار می‌سازد**.
۴. حالت **آفلاین** (نصب/آپدیت از zip محلی)، منوی **آینه** برای شبکهٔ محدود (آینه‌های npm/apt/Node ایرانی)، و **بازیابی بکاپ هنگام نصب**.
۵. آپدیت: بکاپ اختیاری قبل از آپدیت، مقایسهٔ نسخه، پرسش برای دانگرید، migration خودکار، ریستارت.
۶. پایان نصب: کادر موفقیت و ساخت کاربر owner.

## جدول ویژگی‌ها: چه کردیم
| ویژگی Songbird | وضعیت در TIKOOTAK |
|---|---|
| فرمان سراسری + منو | ✅ **اضافه شد** `sudo tikootak` (`scripts/tikootak.sh`) |
| آپدیت/دانگرید با مقایسهٔ نسخه | ✅ اضافه شد: `tikootak update فایل.tar.gz` (آفلاین‌محور؛ فایل `VERSION`) |
| بکاپ قبل از آپدیت | ✅ اجباری (قابل رد با `--no-backup`) |
| — (Songbird ندارد) | ✅ **برگشت خودکار** اگر بعد از آپدیت doctor سبز نشد؛ `tikootak rollback`؛ نگه‌داری ۳ نسخهٔ کد |
| آینه‌ها برای شبکهٔ محدود | ✅ `tikootak mirrors set/show/clear` (npm/apt/Docker) |
| منوی لاگ | ✅ `tikootak logs [سرویس]` |
| ویرایش تنظیمات + اعمال | ✅ `tikootak settings` (با نسخهٔ پشتیبان `.env`) |
| حالت آفلاین | ✅ از قبل داشتیم (`pack-offline.sh` / `offline-images.tar.gz`) |
| بازیابی بکاپ هنگام نصب | ✅ از قبل: `restore.sh` / `migrate.sh` (بکاپ رمزشده + checksum) |
| تست اسکریپت‌ها (bats) | ✅ `tests/scripts/tikootak-update.test.sh` (۹ تست با docker جعلی) |
| SECURITY.md / CHANGELOG | ✅ اضافه شد |
| ثبت‌نام باز/بسته، ban، verify کاربر، ساخت کاربر | ✅ از قبل در `admin.sh` و پنل |
| لاگ ممیزی (audit) در DB | ✅ از قبل |
| تنظیمات runtime در پنل | ✅ بخشی (ثبت‌نام/سقف‌ها)؛ بقیه ↓ |

## ویژگی‌های اپ که برای DeepSeek مرحله‌بندی شد (`docs/DEEPSEEK-UPDATE-PROMPT.md` و تحلیل کامل در `docs/ANALYSIS-SONGBIRD-VS-TIKOOTAK.md`)
به ترتیب ارزش برای شرایط ایران:
1. **Services tab در پنل ادمین**: سلامت Synapse/LiveKit/Postgres/دیسک/TURN با یک نگاه (Songbird: Postgres ping، TURN health).
2. **نگه‌داری خودکار (retention)**: پاک‌کردن رسانه/پست‌های قدیمی بعد از N روز + سقف حجم آپلود قابل‌تنظیم از پنل؛ دیسک ۸۰ گیگ را حفظ می‌کند.
3. **تنظیمات تماس**: روشن/خاموش تماس و ویدیو، حداکثر مدت تماس، صفحهٔ **تاریخچهٔ تماس**.
4. **صف پیام‌های ارسال‌نشده (offline-first)**: «در حال ارسال»، ارسال دوباره خودکار، ماندن در حساب هنگام قطعی (برای اینترنت ناپایدار حیاتی است).
5. **نقش‌ها**: owner / admin / moderator با دسترسی تفکیک‌شده + «claim» اضطراری ادمین با توکن (برای وقتی SSH ندارید).
6. **نشان تأییدشده (verified)** برای کاربر/کانال.
7. **رمزنگاری at-rest رسانهٔ gateway** (کلید در `.env`، داخل بکاپ).
8. (بعداً) **ذخیرهٔ شیء S3** (آروان Object Storage) برای خالی‌کردن دیسک؛ **ترنسکود ویدیو** در worker جدا؛ **کانال‌های broadcast**؛ **Web Push** با پروکسی (FCM در ایران محدود است).

## چیزهایی که عمداً برنداشتیم
- نصب با `curl | bash` از GitHub: GitHub/نصب‌کنندهٔ راه دور ممکن است فیلتر شود؛ مدل ما فایل tar + `tikootak update` است.
- Nginx/systemd/Node مستقیم روی میزبان: ما Docker Compose داریم (جابه‌جایی ساده‌تر).
- Remote Channel تلگرام: مفید ولی بزرگ و خارج از اولویت.
- SQLite در حافظه: ما Postgres داریم.

## ایده‌های بالقوه (تأییدنشده)
- Songbird برای IP به‌جای دامنه گواهی کوتاه‌مدت ۶روزه با `lego` می‌گیرد؛ اگر دامنه فیلتر شد، سرور با IP هم بالا بیاید. نیاز به بررسی پشتیبانی Caddy/Let's Encrypt دارد.
- آینه‌های ایرانی که مستندات Songbird پیشنهاد می‌دهد (npm: `package-mirror.liara.ir`، apt: `ubuntu.pars.host`): **من تست نکرده‌ام**؛ روی سرور با `tikootak mirrors set` امتحان کن.
