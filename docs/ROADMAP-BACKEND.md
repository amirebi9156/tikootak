## معماری فعلی (خلاصه)
Caddy (HTTPS، فایل‌های وب) ← Gateway (Node/Express + SQLite: دعوت، فید، موزیک، استوری، اعلان، گزارش، ادمین) ← Synapse + Postgres (چت و حساب) ← LiveKit (تماس).
احراز هویت: توکن Matrix؛ gateway با `whoami` از Synapse تأییدش می‌کند. لینک مدیا با HMAC امضا و تاریخ‌دار است.

## یافته‌های بررسی اولیه (از خواندن کد)

**نقاط قوت:** ثبت‌نام Synapse بسته و فقط با کد دعوت؛ فدراسیون خاموش؛ API ادمین Synapse در Caddy مسدود؛ مقایسهٔ زمان‌ثابت کلید ادمین؛ rate limit روی ثبت‌نام/ورود/ادمین/توکن تماس؛ سقف حجم و سهمیهٔ کاربر؛ لینک مدیا امضاشده؛ `nosniff`؛ پاکسازی فایل‌های یتیم؛ رمزها خودکار ساخته می‌شوند؛ پشتیبان با `chmod 600`.

**ضعف‌ها / خالی‌ها:**
1. 🔴 هیچ هدر امنیتی (CSP، HSTS، X-Frame-Options، Referrer-Policy، Permissions-Policy) در Caddy نیست.
2. 🔴 نوع فایل آپلودی فقط از هدر Content-Type خوانده می‌شود، محتوا (magic bytes) بررسی نمی‌شود.
3. 🔴 پنل/APIهای ادمین از اینترنت باز هستند (فقط پشت یک کلید). باید محدود به IP یا یک کلید قوی‌تر + لاگ شوند.
4. 🔴 کانتینر gateway با کاربر root اجرا می‌شود؛ فایل‌سیستم قابل‌نوشتن است.
5. 🟠 فایروال سرور (ufw) و fail2ban در اسکریپت نصب نیست؛ پورت SSH بی‌حفاظ.
6. 🟠 سیاست رمز: فقط طول ≥۸؛ قفل‌شدن حساب بعد از تلاش ناموفق فقط براساس IP است (رفتار Synapse هم هست).
7. 🟠 ثبت لاگ امنیتی (ورود ناموفق، ادمین، بن، حذف) نیست؛ لاگ‌ها چرخش ندارند.
8. 🟠 پشتیبان: فقط محلی/restic اختیاری؛ تست بازیابی خودکار نیست؛ رمزگذاری پشتیبان نیست.
9. 🟠 تصویر Docker با تگ `latest` (Synapse/LiveKit): ارتقای ناخواسته. باید نسخه ثابت شود.
10. 🟠 ffmpeg روی فایل کاربر اجرا می‌شود؛ محدودیت زمان/حافظه/CPU در transcode باید بازبینی شود.
11. 🟢 پیام‌های ناپدیدشونده فقط وقتی برنامهٔ فرستنده باز است از سرور حذف می‌شوند.
12. 🟢 آپلود قابل‌ادامه، اعلان پوش، ذخیرهٔ پست (bookmark) وجود ندارد.
