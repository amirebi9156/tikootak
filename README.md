# TIKOOTAK (نام‌های قبلی: TIKOTAK، همدم)

رابط کاربری سبز تیره/روشن/OLED است؛ رنگ‌ها و فونت‌ها در `web-src/src/theme.css` (متغیرهای `:root`) هستند.

پلتفرم چت و تماس گروهی خصوصی روی سرور خودت. ثبت‌نام فقط با کد دعوت. دامنه: `tikootak.ir`

## اجزا
- **Caddy**: HTTPS و مسیریابی (یک دامنه برای همه‌چیز)
- **Synapse (Matrix) + Postgres**: چت، گروه، رمزنگاری سرتاسری، بدون federation
- **LiveKit**: تماس گروهی و TURN داخلی
- **Gateway**: ثبت‌نام با کد دعوت، لاگین، توکن تماس، API ادمین
- **web/dist**: رابط کاربری کامل (چت، فید، استوری، موزیک، پروفایل، اعلان‌ها، تنظیمات)

## نصب روی سرور خام (یک دستور)
راهنمای کامل قدم‌به‌قدم: `docs/INSTALL-FA.md`
```bash
tar -xf tikootak-full-X.Y.Z.tar && cd tikootak      # کیت کامل آفلاین (یا tar.gz معمولی release)
sudo ./scripts/bootstrap.sh --domain tikootak.ir --yes
```
Docker، فایروال، HTTPS، بکاپ شبانه و فرمان `tikootak` خودکار نصب می‌شوند و در پایان یک کد دعوت چاپ می‌شود.

## حالت آفلاین (جنگ / قطع اینترنت بین‌المللی)
اگه کنار `bootstrap.sh` فایل `offline-images.tar.gz` باشد (کیت کامل)، نصب خودکار **آفلاین** انجام می‌شود:
هیچ دانلودی از GitHub، Docker Hub، npm یا apt لازم نیست و حتی Docker از بسته‌های داخل کیت نصب می‌شود.
- ساخت کیت: `./scripts/make-kit.sh --with-docker-debs ubuntu:24.04,ubuntu:22.04` (یا از Release در GitHub، فایل `tikootak-full-*.tar`).
- گواهی اضطراری HTTPS: `sudo tikootak cert export-auto` (گواهی فعلی را برای روز قطعی ذخیره می‌کند)؛ نصب دستی: `bootstrap.sh --cert fullchain.pem --key key.pem`.
- آینه‌های داخلی: `tikootak mirrors test`.
- آمادگی: `sudo tikootak ready` (کیت، گواهی، بکاپ، دیسک، ساعت را چک می‌کند).

راهنمای کامل فارسی: **`docs/OFFLINE-FA.md`**

## گواهی HTTPS
مرورگر برای میکروفون و دوربین حتما HTTPS می‌خواد.
اگه سرور به Let's Encrypt دسترسی نداره، `sudo tikootak cert` (status / install / use-manual / howto) را ببین؛
گواهی دستی در `certs/cert.pem` و `certs/key.pem` است و `CADDYFILE=./Caddyfile.manual-cert` در `.env` می‌شود.

## پورت‌هایی که باید باز باشن
`80/tcp`، `443/tcp`، `7881/tcp`، `7882/udp`، `3478/udp`، `30000-30100/udp`

## کد دعوت (ادمین)
```bash
source .env
curl -X POST https://$DOMAIN/api/admin/invites \
  -H "x-admin-key: $GATEWAY_ADMIN_KEY" -H 'content-type: application/json' \
  -d '{"max_uses":3,"expires_days":7,"note":"دوستان"}'
```
لیست: `GET /api/admin/invites` و ابطال: `DELETE /api/admin/invites/<CODE>`

## مدیریت بعد از نصب: `sudo tikootak`
بعد از نصب، یک فرمان سراسری ساخته می‌شود (اگر نشد: `sudo ./scripts/tikootak.sh install-cli`).
- `sudo tikootak` منوی کامل؛ `tikootak status` وضعیت سریع.
- `sudo tikootak update ~/tikootak-UI34.tar.gz` ارتقا/دانگرید: بکاپ ← جایگزینی کد (`.env` و داده حفظ) ← ساخت ← doctor؛ اگر سالم نشد **برگشت خودکار**. `tikootak rollback` برگشت دستی.
- `tikootak mirrors set|show|clear` آینهٔ Docker/npm/apt، `tikootak logs [سرویس]`، `tikootak settings`، `tikootak signup close`.
- بررسی Songbird و ویژگی‌های برداشته‌شده: `docs/SONGBIRD-ANALYSIS.md`.

## بکاپ و جابجایی سرور
- بکاپ: `./scripts/backup.sh` (می‌تونی با cron شبانه بذاری)
- سرور جدید: Docker نصب کن، repo رو کلون کن، فایل بکاپ رو بیار و `./scripts/restore.sh <فایل>`
- بعد DNS دامنه رو به IP جدید بده (TTL کم بذار تا سریع جابجا بشه)

| `POST /api/feed/posts/:id/share` | ثبت سیگنال اشتراک‌گذاری |
| `POST /api/feed/posts/:id/not-interested` | پنهان‌کردن پست و کم‌کردن علاقه |

| `GET /api/feed/thumb/:id` | دریافت پوستر امضادار پست |
| `GET/POST/DELETE /api/blocks` | فهرست، بلاک و رفع بلاک کاربر |
| `GET /api/admin/bans` و `POST/DELETE /api/admin/users/:id/ban` | بن و رفع بن (ادمین) |

## رابط کاربری (web-src و web/dist)
- کد رابط کاربری (React) در `web-src/` است و نسخه آماده اجرا در `web/dist/` که Caddy سرو می‌کند.
- برای اجرا فقط `web/dist` لازم است. اگر کد `web-src` را تغییر دادی: `./scripts/build-web.sh`
- ساختار کد: `Auth.jsx` (ورود و ثبت‌نام)، `Shell.jsx` (لیست اتاق‌ها)، `Chat.jsx` (چت)، `api.js` (ارتباط با Gateway)، `useMatrix.js` (اتصال به Synapse)، `styles.css` (ظاهر).
- فونت (وزیرمتن) داخل خود برنامه است و هیچ سرویس خارجی (CDN و فونت گوگل) استفاده نمی‌شود.

### محدودیت‌های نسخه فعلی
- پیام‌ها هنوز رمزنگاری سرتاسری نیستند (سرور می‌تواند آن‌ها را ببیند). رمزنگاری در مرحله‌ای جدا اضافه می‌شود.
- ارسال تصویر و فایل هنوز نیست.

## تماس گروهی
- دکمه تلفن بالای هر اتاق تماس را شروع می‌کند. با شروع تماس یک کارت «پیوستن» در چت اتاق می‌افتد و بقیه با آن وارد می‌شوند.
- داخل تماس: میکروفون، دوربین، اشتراک صفحه و قطع تماس. با «بازگشت به چت» تماس ادامه دارد و یک نوار زرد بالای صفحه نشان می‌دهد در تماس هستی.
- مرورگر برای میکروفون و دوربین فقط روی HTTPS معتبر (یا localhost) اجازه می‌دهد.
- پورت‌های لازم: `7881/tcp`، `7882/udp`، `3478/udp`. بازه `30000-30100/udp` برای relay مربوط به TURN است و برای کاربرانی که پشت NAT سخت هستند لازم است.
- محدودیت: قبل از پیوستن نمی‌شود دید چه کسانی در تماس هستند، و کارت تماس بعد از تمام شدن تماس در تاریخچه می‌ماند.

## عیب‌یابی
- `./scripts/doctor.sh` سلامت همه‌چیز را چک می‌کند و برای هر مشکل پیشنهاد رفع می‌دهد.
- راهنمای کامل (عیب‌یابی، بازیابی رمز، جابجایی سرور، کیت بقا بدون اینترنت): `docs/RUNBOOK.md`

## رمزنگاری سرتاسری (E2EE)

- اتاق‌هایی که از این نسخه به بعد ساخته شوند رمزنگاری‌اند (نشان 🔒 کنار تعداد اعضا). سرور فقط متن رمزشده می‌بیند، حتی تو به‌عنوان مدیر سرور نمی‌توانی پیام‌ها را بخوانی.
- اتاق‌های قدیمی (ساخته‌شده قبل از این نسخه) رمزنگاری نمی‌شوند. برای رمزنگاری، اتاق جدید بساز.
- کلیدهای رمزگشایی داخل مرورگر (IndexedDB) هستند. بعد از اولین ورود، بنر زرد «کلید بازیابی نساخته‌ای» می‌آید؛ آن را بساز و جای امن نگه دار.
- با کلید بازیابی، روی دستگاه یا مرورگر جدید پیام‌های قبلی باز می‌شوند. بدون آن، پیام‌های قبلی روی دستگاه جدید باز نمی‌شوند. بکاپ سرور هم این مشکل را حل نمی‌کند چون سرور کلید ندارد.
- خروج از حساب: اگر کلید بازیابی ساخته باشی، کلیدهای محلی پاک می‌شوند (امن برای رایانه مشترک)؛ اگر نساخته باشی نگه داشته می‌شوند.
- فراموشی رمز عبور (طبق RUNBOOK) فقط ورود را برمی‌گرداند؛ پیام‌های قدیمی فقط با کلید بازیابی باز می‌شوند.

## ارسال عکس و فایل

- دکمه گیره کنار جعبه پیام، یا Paste کردن عکس (Ctrl+V). حداکثر ۵۰ مگابایت برای هر فایل (سقف سرور `max_upload_size` در `templates/homeserver.yaml.tpl` است).
- در اتاق رمزنگاری‌شده، فایل در مرورگر رمز می‌شود و نام و محتوایش روی سرور خوانا نیست. در اتاق قدیمی (بدون رمز) فایل ساده ذخیره می‌شود.
- عکس‌های زیر ۸ مگابایت خودکار باز می‌شوند، بقیه با دکمه «نمایش/دریافت».
- فایل‌ها در پوشه `data/synapse/media_store` هستند و در بکاپ می‌آیند. حجم بکاپ با فایل‌ها زیاد می‌شود.

## فید ویدیو و عکس

- دکمه فیلم (بالای لیست اتاق‌ها) فید را باز می‌کند. هر کاربر واردشده همه پست‌ها را می‌بیند؛ می‌تواند لایک و نظر بدهد و پست خودش را پاک کند.
- فرمت‌ها: mp4، webm، mov، jpg، png، webp، gif. سقف ۱۵۰ مگابایت (با `FEED_MAX_MB` در `.env` عوض می‌شود).
- **مهم:** ویدیو تبدیل (transcode) نمی‌شود، همان فایل پخش می‌شود. ویدیوی گوشی‌ها معمولاً H.264 است و همه‌جا پخش می‌شود؛ ولی HEVC (بعضی آیفون‌ها) روی بعضی مرورگرهای ویندوز پخش نمی‌شود. حجم زیاد هم اینترنت داخلی را پر می‌کند؛ بهتر است ویدیوها کوتاه باشند.
- فایل‌ها در `data/gateway/feed` و اطلاعات (لایک، نظر) در `data/gateway/gateway.db` هستند و در بکاپ می‌آیند. حجم بکاپ با ویدیوها زیاد می‌شود؛ اگر زیاد شد، پوشه `backups/` را هر چند وقت پاک کن.
- پست‌ها رمزنگاری سرتاسری نیستند (برخلاف چت). مدیر سرور می‌تواند فایل‌ها را ببیند. این فید برای محتوای عمومی بین دوستان است.

## موزیک و پلی‌لیست

- دکمه نت موسیقی (بالای لیست اتاق‌ها). سه بخش: «پلی‌لیست‌های من»، «عمومی» (پلی‌لیست‌های عمومی همه کاربران) و «آهنگ‌های من» (آپلود آهنگ).
- فرمت‌ها: mp3، m4a، aac، ogg، opus، wav، flac. سقف هر آهنگ ۶۰ مگابایت (`MUSIC_MAX_MB` در `.env`).
- پلی‌لیست خصوصی فقط برای صاحبش است. عمومی را همه می‌توانند ببینند و گوش بدهند. می‌شود هر وقت خصوصی/عمومی‌اش کرد.
- هر کاربر فقط آهنگ‌های خودش را پاک می‌کند. آهنگ پلی‌لیست عمومی دیگران را با دکمه «+ پلی‌لیست» کنار آهنگ می‌شود به لیست خودت اضافه کرد.
- پخش‌کننده پایین صفحه می‌ماند و وقتی بین چت و فید می‌روی ادامه دارد. آهنگ بعدی خودکار پخش می‌شود. روی گوشی از قفل‌صفحه هم کنترل می‌شود.
- فایل‌ها در `data/gateway/music` هستند و در بکاپ می‌آیند. آهنگ‌ها رمزنگاری سرتاسری نیستند.
- دقت: آپلود آهنگ دارای حق کپی‌رایت با خود کاربر است؛ مدیر سرور می‌تواند همه فایل‌ها را ببیند و پاک کند.

## مدیریت و تست

- `./scripts/admin.sh` برای آمار، فهرست کاربران، ساخت کد دعوت، حذف محتوا و ban کردن کاربر.
- `docs/TESTING.md` چک‌لیست تست کامل روی کامپیوتر خودت.

## پروفایل، آیدی و پیام خصوصی

- آیدی هر نفر همان نام کاربری اوست (مثلاً `@ali`). دکمه «افراد» با آیدی یا نام جستجو می‌کند.
- پروفایل: عکس (خودکار مربعی و کوچک می‌شود)، نام نمایشی، بیو (۱۵۰ حرف)، تعداد پست و دنبال‌کننده، شبکه پست‌ها. با کلیک روی عکس یا نام هر کس (پست، نظر، لیست اعضا) صفحه‌اش باز می‌شود.
- از صفحه پروفایل «پیام» یک گفتگوی خصوصی رمزنگاری‌شده می‌سازد (اگر قبلاً هست باز می‌شود).
- دنبال کردن: تب «دنبال‌شده‌ها» در فید فقط پست آن‌ها را نشان می‌دهد.
- فید دو حالت دارد: «ریلز» (هر پست یک صفحه، بالا/پایین) و «شبکه». انتخاب در مرورگر یادت می‌ماند.
- نظرها قابل لایک‌اند؛ صاحب نظر و صاحب پست می‌توانند نظر را پاک کنند.
- عکس‌های پروفایل در `data/gateway/avatars` هستند و در بکاپ می‌آیند.

## کاور آهنگ

- موقع آپلود، عنوان، خواننده و عکس کاور از داخل خود فایل (mp3، m4a، flac) خوانده می‌شود، پس بیشتر آهنگ‌های دانلودی خودکار کاور دارند. فایل بدون کاور، مربع رنگی با نت موسیقی می‌گیرد.
- کاور در لیست آهنگ‌ها، پخش‌کننده پایین صفحه، قفل‌صفحه گوشی و پلی‌لیست (کاشی ۴ کاور) دیده می‌شود.
- فایل‌های کاور در `data/gateway/covers` هستند.

## استوری ۲۴ ساعته

- نوار استوری بالای صفحه «فید» است. «+» استوری جدید می‌گذارد (عکس یا ویدیو تا ۶۰ ثانیه، با متن کوتاه).
- حلقه رنگی یعنی هنوز ندیده‌ای؛ بعد از دیدن خاکستری می‌شود. استوری خودت، لیست بیننده‌ها و حذف دارد.
- در نمایشگر: لمس طرف چپ بعدی، طرف راست قبلی، نگه داشتن مکث می‌کند، کلید جهت‌دار و Esc هم کار می‌کنند.
- بعد از ۲۴ ساعت فایل و ردیف خودکار پاک می‌شود (هر ۱۰ دقیقه و موقع روشن شدن gateway). سقف حجم `STORY_MAX_MB` (پیش‌فرض ۵۰).
- فایل‌ها در `data/gateway/stories` هستند. استوری‌ها رمزنگاری سرتاسری نیستند.

## امکانات چت

- **واکنش**: روی پیام بزن تا نوار عملیات باز شود؛ ۶ ایموجی. روی ایموجی زیر پیام بزنی واکنش خودت اضافه یا برداشته می‌شود.
- **پاسخ (ریپلای)**: «پاسخ» → نقل‌قول بالای پیام می‌آید و با کلیک به پیام اصلی می‌پرد.
- **ویرایش و حذف**: فقط پیام‌های خودت. ویرایش‌شده برچسب دارد. حذف برای همه است.
- **پین**: «پین» پیام را به نوار بالای چت می‌برد. در اتاق‌های جدید همه اعضا می‌توانند پین کنند؛ در اتاق‌های قدیمی فقط سازنده.
- **ویس**: وقتی کادر پیام خالی است دکمه 🎤 می‌آید. ضبط، 🗑 لغو، ارسال با دکمه ارسال (حداکثر ۵ دقیقه). به مرورگر اجازه میکروفون بده (روی `https://` یا `localhost`).
- در اتاق رمزنگاری‌شده متن، ویرایش، فایل و ویس رمز می‌شوند. **واکنش‌ها** (ایموجی و اینکه به کدام پیام) و پین‌ها مطابق استاندارد Matrix روی سرور رمز نمی‌شوند؛ مدیر سرور فقط همین ایموجی‌ها را می‌بیند.


## اعلان‌ها

- زنگ بالای ستون کناری و ردیف «اعلان‌ها» بالای لیست گفتگوها. عدد کنار زنگ تعداد خوانده‌نشده‌هاست و هر ۳۰ ثانیه (و با برگشتن به تب) تازه می‌شود.
- اعلان برای: لایک پست، نظر روی پست، لایک نظر و دنبال کردن. با کلیک روی اعلان لایک/نظر همان پست باز می‌شود و با کلیک روی اعلان دنبال‌کردن پروفایل آن شخص.
- باز کردن پنل، همه را خوانده می‌کند ولی نقطه‌ی هر مورد جدید می‌ماند. «پاک کردن همه» فهرست را خالی می‌کند.
- اعلان‌های تکراری (همان شخص روی همان محتوا) تا یک ساعت دوباره ثبت نمی‌شوند. با حذف پست، اعلان‌های مربوط به آن هم پاک می‌شوند.
- اعلان‌ها در `data/gateway/gateway.db` (جدول `notifications`) هستند و در بکاپ می‌آیند.

## تنظیمات

- دسکتاپ: چرخ‌دنده کنار کارت نام کاربر. موبایل: دکمه «+» → «تنظیمات». یا از پروفایل.
- **حساب**: تغییر نام نمایشی. عکس و بیو از «ویرایش پروفایل» در صفحه پروفایل.
- **امنیت**: تغییر رمز عبور (رمز فعلی لازم است)، فهرست دستگاه‌های واردشده با زمان آخرین فعالیت و «خروج» از دستگاه‌های دیگر، و ساخت/بازیابی کلید رمزنگاری.
- **ظاهر**: تم تیره یا روشن.
- **درباره**: نسخه و خروج از حساب.
- تغییر رمز پیام‌های رمزنگاری‌شده را پاک نمی‌کند؛ کلیدها در مرورگر و کلید بازیابی جای دیگری هستند.


## نمایش عکس و ویدیو در چت

- روی عکس یا کارت ویدیو بزن: داخل همان چت و بدون تب جدید باز می‌شود. ویدیو همان‌جا پخش می‌شود، عکس با دکمه ذره‌بین بزرگ می‌شود و دکمه ذخیره فایل را دانلود می‌کند.
- در اتاق رمزنگاری‌شده فایل اول در مرورگر رمزگشایی می‌شود و بعد نمایش داده می‌شود؛ سرور محتوای خام را نمی‌بیند.
- ویدیوهای جدید در چت با نوع `m.video` فرستاده می‌شوند. ویدیوهای قدیمی‌تر (که `m.file` با mime ویدیو هستند) هم خودکار به‌عنوان ویدیو شناخته می‌شوند.
- دکمه سنجاق کنار کادر پیام سه گزینه دارد: تصویر، موزیک (کتابخانه) و فایل از دستگاه. چیپ‌های قبلی زیر چت حذف شدند.

## زبان و ظاهر

- دکمه «EN / فا» بالای ستون کناری و در صفحه ورود و معرفی. با زدنش صفحه بارگذاری مجدد می‌شود و انتخاب در مرورگر می‌ماند.
- زبان پیش‌فرض از زبان مرورگر می‌آید: فارسی → فارسی، بقیه → انگلیسی. در حالت انگلیسی کل صفحه چپ‌به‌راست می‌شود.
- ترجمه‌ها در `web-src/src/en.js` هستند و کلیدشان همان متن فارسی است. هر متنی که ترجمه نداشته باشد فارسی نشان داده می‌شود. برای تغییر یک ترجمه فقط همان خط را عوض کن و `./scripts/build-web.sh` را بزن.
- پیام‌ها، پست‌ها، نام کاربران و آهنگ‌های کاربرها ترجمه نمی‌شوند.
- تم تیره/روشن از «تنظیمات → ظاهر و زبان». ظاهر برنامه (گوشه‌های گرد، کارت‌ها، فاصله‌ها و دکمه‌ها) در `web-src/src/theme.css` است و بعد از `styles.css` بارگذاری می‌شود.


## فید هوشمند (برای تو)

- تب پیش‌فرض فید «برای تو» است. سرور از حدود ۵۰۰ پست اخیر کاندید می‌گیرد و با یک امتیاز ساده رتبه می‌دهد: علاقه به نویسنده، هم‌پوشانی هشتگ‌ها، سرعت تعامل (لایک/نظر/اشتراک با افت زمانی)، تازگی، دنبال‌کردن نویسنده، پنالتی پست‌های دیده‌شده و پست خودت.
- سیگنال‌ها: درصد تماشای ویدیو (مهم‌ترین)، لایک، نظر، اشتراک در چت، دنبال‌کردن، «علاقه ندارم».
- وزن علاقه‌ها در جدول `interests` با نیمه‌عمر ۱۴ روز کم می‌شود؛ کلیدها `a:<user>` و `t:<hashtag>` هستند.
- تنوع: هیچ نویسنده‌ای بیشتر از ۲ پست پشت‌سرهم نمی‌آید و حدود ۱۵٪ فید به نویسنده‌های ناشناخته (کشف) اختصاص دارد.
- کلاینت رویدادهای تماشا را دسته‌ای (هر ۸ ثانیه یا ۲۰ رویداد) به `/api/feed/views` می‌فرستد و پست‌های دیده‌شده را با `/api/feed/seen` علامت می‌زند. صفحه‌بندی با `exclude` انجام می‌شود تا پست تکراری نیاید.
- «علاقه ندارم» پست را برای همیشه از فید همان کاربر پنهان می‌کند و وزن نویسنده/هشتگ را کم می‌کند.
- «لایک مشترک»: زیر هر پست نشان داده می‌شود کدام یک از دنبال‌شده‌های تو آن پست را لایک کرده‌اند.
- در اکسپلور هم وقتی جستجو خالی است، همان فید هوشمند به‌صورت شبکه نمایش داده می‌شود و چیپ‌های علاقه بالای آن می‌آیند.

## درخواست پیام و بلاک

- پیام خصوصی از کسی که دنبالش نمی‌کنی در **زنگوله → درخواست‌ها** می‌آید؛ با «قبول» به لیست پیام‌ها اضافه می‌شود و با «رد» بسته و فراموش می‌شود. اگر طرف را دنبال کنی، مستقیم به لیست پیام‌ها می‌آید. ردیف‌های «اعلان‌ها» و «درخواست‌های پیام» از بالای لیست گفتگوها حذف شده‌اند.
- بلاک: از پروفایل (دکمه «بلاک») یا منوی سه‌نقطهٔ هر پست. کاربر بلاک‌شده از فید، پروفایل، جستجو و کامنت‌ها حذف می‌شود، دنبال‌کردن دوطرفه قطع می‌شود و همهٔ گفتگوها/دعوت‌های خصوصی‌اش بسته می‌شود. در تنظیمات → «کاربران بلاک‌شده» می‌توانی رفع بلاک کنی.
- بلاک با «بن ادمین» فرق دارد: بن کل دسترسی به gateway را می‌بندد، بلاک فقط رابطهٔ همان دو کاربر را.

## امنیت و سقف مصرف (F1)

- بیش از ۴۰ توکن نامعتبر در دقیقه از یک IP → ۴۲۹؛ توکن نامعتبر ۳۰ ثانیه کش می‌شود تا به Synapse فشار نیاید.
- کلید امضای لینک‌های مدیا جدا از کلید ادمین است و خودکار در `data/gateway/media.key` ساخته می‌شود (`MEDIA_SECRET` هم قابل تنظیم است).
- کلید ادمین: ۶۰ درخواست در دقیقه و ۲۰ حدس غلط در ۱۵ دقیقه → ۴۲۹.
- سقف مجموع پست + آهنگ + استوری هر کاربر با `USER_QUOTA_MB` (پیش‌فرض ۳۰۰۰ مگابایت). خطای `quota_exceeded` به کاربر نمایش داده می‌شود.
- جستجوی افراد حداقل ۲ حرف و حداکثر ۱۵ نتیجه، از فهرست نام داخل SQLite و بدون تماس به Synapse.
- بن/رفع بن کاربر از پنل ادمین؛ کاربر بن‌شده از فید، موزیک، استوری، پروفایل و جستجو بیرون می‌ماند (حساب Matrix بسته نمی‌شود).
- همهٔ خطاها JSON هستند، تماس با Synapse مهلت ۱۰ ثانیه دارد، فایل‌های نیمه‌کاره هنگام بالا آمدن پاک می‌شوند، صفحه‌بندی فید پست‌های هم‌ثانیه را جا نمی‌اندازد و حذف پست لایک نظرها را هم پاک می‌کند.
- اگر بازیابی کلید صفر کلید پیدا کند، پیام راهنما و دکمه «تلاش دوباره» نشان داده می‌شود.

## اگر پیام‌های رمزنگاری‌شده بین دو نفر نمی‌رسند

- پیام‌ها روی سرور ذخیره می‌شوند؛ اگر دستگاهِ گیرنده کلید رمزنگاری نداشته باشد، پیام ذخیره می‌شود ولی باز نمی‌شود (نه اینکه ارسال نشده باشد).
- از این نسخه، استور رمزنگاری برای هر دستگاه جداست. اگر سرور برای آن دستگاه کلید نداشته باشد، استور تازه ساخته و کلیدها آپلود می‌شوند؛ پس بعد از آپدیت یک‌بار Ctrl+Shift+R بزن.
- پیام‌های قدیمی که با کلید قبلی رمز شده‌اند ممکن است باز نشوند: تنظیمات → «بازیابی با کلید» و کلید بازیابی حساب را وارد کن. پیام‌های جدید باید عادی باز شوند.
- اگر بنر «رمزنگاری روی این دستگاه فعال نشد» دیدی، صفحه را رفرش کن؛ اگر ماند، خارج و دوباره وارد شو. اگر باز هم بود خطای کنسول را بفرست.
- برای تست دو کاربر روی یک کامپیوتر، از دو پروفایل مرورگر جدا (یا یکی Incognito) استفاده کن؛ localStorage بین تب‌های یک پروفایل مشترک است.
- ممکن است بین دو نفر چند اتاق قدیمی مانده باشد؛ اتاقی را باز کن که آخرین پیام طرف مقابل در آن است.


## اشتراک‌گذاری پست، پیش‌نمایش ویدیو و زنگوله

- **اشتراک پست در چت:** کارت پست در حباب چت یک کارت جدا با تصویر/پوستر، نوع (ویدیو/عکس)، نویسنده، توضیح، تعداد لایک و دکمه «مشاهده» است. قبلاً کلاس `post` با استایل پست فید تداخل داشت و کارت را خراب می‌کرد؛ حذف شد.
- **پیش‌نمایش ویدیو در چت:** هنگام ارسال ویدیو، مرورگر یک فریم را به‌صورت WebP (حدود ۱۵ تا ۴۰ کیلوبایت) می‌گیرد. در اتاق رمزنگاری‌شده این پوستر جداگانه با AES رمز و در `info.thumbnail_file` ارسال می‌شود؛ در اتاق معمولی `info.thumbnail_url`. گیرنده فقط پوستر را دانلود می‌کند و تا کلیک روی کارت، ویدیوی کامل دانلود نمی‌شود. ویدیوهای قدیمی که پوستر ندارند، فقط کارت با دکمه پخش نشان می‌دهند.
- **زنگوله:** اعلان‌های لایک/نظر/فالو و درخواست‌های پیام در یک پنل با دو تب «اعلان‌ها» و «درخواست‌ها» هستند. بج زنگوله مجموع اعلان‌های نخوانده و درخواست‌های در انتظار است. ردیف‌های جداگانه بالای گفتگوها حذف شدند.

## کاهش حجم داده (G)

پیاده‌سازی‌شده:

- **فشرده‌سازی عکس سمت مرورگر:** همه عکس‌های پست، استوری و چت قبل از آپلود به WebP با حداکثر ۱۶۰۰ پیکسل و کیفیت ۰٫۸۲ تبدیل می‌شوند (در تست ۱۴۰ کیلوبایت → ۲۷ کیلوبایت). GIF و SVG دست‌نخورده می‌مانند.
- **پوستر/تامبنیل ویدیو:** پوستر WebP برای پست‌های فید (حداکثر ۴۸۰ پیکسل) و برای ویدیوی چت (رمزنگاری‌شده در DM). در فید با `poster` و در چت با `thumbnail_file` نمایش داده می‌شود.
- **سقف ۶۰ ثانیه برای ویدیوی پست** و سقف ۱۵۰ مگابایت قبل از آپلود.
- **حذف تکراری آهنگ با SHA-256:** آپلود دوم یک فایل یکسان، فایل جدید را دور می‌ریزد و رکورد جدید به همان فایل اشاره می‌کند. حذف هر رکورد فقط وقتی فایل را پاک می‌کند که رکورد دیگری به آن اشاره نکند (شامل حذف ادمین).
- **تبدیل ویدیو به H.264 ≤720p** (پست فید/ریلز و استوری) با ffmpeg در صف پایدار SQLite (`transcode_jobs`): یک worker، `nice -n 19`، یک thread، `veryfast`، CRF 28، صدای AAC 96k، faststart، سقف سخت ۱۸۰ ثانیه. فقط اگر خروجی کوچک‌تر بود جایگزین می‌شود (اتمیک) و اصل تا پایان سالم می‌ماند. ویدیوی از قبل H.264 ≤720p و کمتر از ۱۰ مگابایت `skipped` می‌شود. `TRANSCODE=0` خاموش می‌کند.
- **نگهداری ۶۰ روزه رسانه چت** در Synapse (`media_retention`: local 60d، remote 14d) و **پاک‌سازی حساب‌های غیرفعال** به‌صورت ابزار دستی در پنل ادمین (فیلتر بیش از ۱۸۰ روز + حذف با تأیید).
- **سقف فضای کاربر** از F1 (`USER_QUOTA_MB`).

باقی‌مانده از رودمپ (مرحله بعد):

- دو کیفیت 480p/720p و انتخاب خودکار بر اساس سرعت.
- لایه‌بندی سرد/Object Storage و CDN برای پست‌های کم‌بازدید.
- پاک‌سازی خودکار حساب‌های غیرفعال (فعلاً فقط ابزار دستی؛ طبق تصمیم پروژه حذف خودکار نداریم).


## پنل مدیریت وب
آدرس `https://<آدرس-سایت>/admin.html` را باز کن و `GATEWAY_ADMIN_KEY` (از فایل `.env`) را وارد کن: گزارش‌ها، کاربران و حجمشان، آمار و ساخت دعوت‌نامه.


## حریم خصوصی استوری و لیست دنبال‌کننده‌ها (F2b)

- هر کاربر در **تنظیمات → حریم خصوصی** انتخاب می‌کند استوری‌اش را «همه» یا «فقط دنبال‌کننده‌هایم» ببینند و می‌تواند لیست دنبال‌کننده/دنبال‌شده‌هایش را پنهان کند.
- در بک‌اند: `GET/PUT /api/privacy` (فقط مقادیر مجاز)، فیلتر استوری در `GET /api/stories`، `POST /api/stories/:id/view` (۴۰۴ برای غیرمجاز) و **media route** (لینک امضاشده هم برای غیرمجاز ۴۰۳ می‌دهد). لیست فالوورها با `hidden:true` و آرایه خالی برمی‌گردد؛ شمارنده‌ها می‌مانند.
- بلاک/بن دوطرفه در استوری و لیست‌ها رعایت می‌شود.
- هشدار: با `media_retention`، رسانه‌های چت قدیمی‌تر از ۶۰ روز پاک می‌شوند؛ این جمله در تنظیمات هم نمایش داده می‌شود.

## تبدیل ویدیو و سازگاری با سرور ضعیف

- **ffmpeg همراه پروژه** در `gateway/bin` است (نسخه ۹.۰.۲ + کتابخانه‌ها + loader) چون apt/Debian در محیط build ما مسدود بود. ایمیج حدود ۹۷ مگابایت بزرگ‌تر می‌شود. ffprobe همراه نیست؛ probe با `ffmpeg -i` انجام می‌شود.
- صف در جدول `transcode_jobs` ذخیره می‌شود؛ بعد از ری‌استارت jobهای running دوباره queued می‌شوند. وقتی `os.loadavg()[0] > 2` باشد worker ۱۵ ثانیه صبر می‌کند تا چت/تماس اولویت داشته باشد.
- `TRANSCODE=0` کل قابلیت را خاموش می‌کند. `TRANSCODE_SKIP_MB` آستانه skip است (پیش‌فرض ۱۰).
- `sweepOrphans` و `sweepThumbs` دست‌نخورده‌اند؛ فایل‌های موقت `.transcode-*` هنگام بالا آمدن پاک می‌شوند و حذف پست job/فایل موقت را پاک می‌کند.
- **محدودیت‌های حافظه** در `docker-compose.yml`: synapse 700m، postgres 300m، livekit 200m، gateway 450m، caddy 64m (قابل تغییر با `SYNAPSE_MEM`، `POSTGRES_MEM`، ...).
- Postgres با `shared_buffers=128MB`، `max_connections=30`، `work_mem=4MB` و `effective_cache_size=512MB` اجرا می‌شود.
- Synapse: `caches.global_factor=0.5`، `presence.enabled=false` و `media_retention` (60d/14d). قالب در `templates/homeserver.yaml.tpl` است و روی نصب فعلی هم اعمال شد (بکاپ: `data/synapse/homeserver.yaml.bak-f2b`).
- **Swap اختیاری:** `sudo sh scripts/setup-swap.sh` یک فایل ۲ گیگ می‌سازد/فعال می‌کند و در `/etc/fstab` ثبت می‌کند؛ اجرای دوباره بی‌خطر است. در `install.sh` خودکار اجرا نمی‌شود.
- **پنل ادمین:** ستون «آخرین فعالیت» (آخرین پست/نظر/آهنگ/استوری/بازدید/ثبت‌نام) و فیلتر «غیرفعال بیش از ۱۸۰ روز»؛ حذف محتوا دستی و با تأیید. آمار `transcode_queued/failed` هم نمایش داده می‌شود.


## CH1: بازطراحی چت (کلید خودکار، سه نوع گفتگو، فوروارد/ذخیره/Mute)

### کلید بازیابی خودکار
- هنگام ثبت‌نام یا اولین ورودِ کاربری که پشتیبان ندارد، پشتیبان کلید **بی‌صدا** با passphrase = رمز عبور ساخته می‌شود. رمز فقط در حافظهٔ همان تب است و در localStorage/لاگ نوشته نمی‌شود.
- در دستگاه جدید، بعد از ورود، کلید Secret Storage از رمز مشتق می‌شود، کلید پشتیبان از SSSS خوانده و پیام‌ها بازیابی می‌شوند. هیچ دیالوگ اجباری وجود ندارد.
- دیالوگ‌های «کلید بازیابی نساخته‌ای» حذف شدند. بخش «پیشرفته» در تنظیمات: نمایش کلید همین نشست (در حافظه)، ساخت کلید دستی جدید و بازیابی دستی. هشدار: فراموشی رمز = از دست رفتن پیام‌های قدیمی.
- تغییر رمز، پشتیبان را با passphrase جدید بازسازی می‌کند (bootstrapSecretStorage با setupNewKeyBackup). **نکته:** آپلود کلیدهای قدیمی به پشتیبان در rust-crypto تنبل است؛ در تستِ تغییر رمز، پیام‌های قدیمی روی دستگاه جدید بلافاصله باز نشدند. این را در گزارش صادقانه ذکر کرده‌ام.
- API نسخهٔ 44: `restoreKeyBackupWithPassphrase` برای auth_data پشتیبان است و برای SSSS با passphrase جواب نمی‌داد؛ مسیر درست: `deriveRecoveryKeyFromPassphrase` + `cryptoCallbacks` + `loadSessionBackupPrivateKeyFromSecretStorage` + `restoreKeyBackup`.

### سه نوع گفتگو
- **پی‌وی**: همان `openDM` با `is_direct` و رمزنگاری.
- **گروه**: خصوصی/عمومی، رمزنگاری اختیاری (پیش‌فرض خاموش)، `history_visibility: shared`؛ عضو جدید در گروه رمزنگاری‌شده تاریخچهٔ قبلی را نمی‌بیند.
- **کانال**: `events_default: 50`، `users_default: 0`، `m.room.message: 50`، `m.reaction: 0`؛ فقط مدیران (≥50) می‌نویسند و اعضا واکنش می‌دهند. رمزنگاری همیشه خاموش. ساختار قدرت شامل سازنده ۱۰۰ (Matrix سازنده را در users نمی‌پذیرد؛ در UI محاسبه می‌شود).
- **کشف**: `publicRooms` برای گروه/کانال عمومی، عضویت با یک دکمه. لینک دعوت `https://site/#/join/<alias>` هنگام باز شدن کاربر را عضو می‌کند.
- **دایرکتوری عمومی**: `room_list_publication_rules` در قالب/کانفیگ Synapse اضافه شد (پیش‌فرض خالی بود و انتشار را ۴۰۳ می‌کرد)؛ فدراسیون خاموش و فهرست فقط برای کاربران واردشده است.
- لیست گفتگوها نشان نوع (👤/👥/📢/🔖) و قفل دارد؛ هدر نوع/عضو/رمزنگاری؛ کانال برای عضو عادی نوار نوشتن ندارد و به‌جای آن پیام راهنما + Mute + تنظیمات دارد.
- تنظیمات گفتگو: نام/توضیح (مدیر)، اعضا و نقش‌ها (مدیر/عضو/حذف برای مدیر)، لینک دعوت، Mute و ترک.

### فوروارد، پیام‌های ذخیره‌شده، Mute
- منوی پیام: «ارسال به…» با انتخاب چند گفتگو و جستجو. رسانه بین اتاق هم‌رمز و غیررمز مستقیماً کپی می‌شود؛ اگر وضعیت رمز فرق کند، فایل دانلود و در مقصد دوباره رمز/آپلود می‌شود. فیلد `ir.tikootak.forwarded_from` و نشان «فورواردشده از …» اضافه شد.
- **ذخیره**: اتاق خصوصی تک‌نفرهٔ رمزنگاری‌شده با account data `ir.tikootak.saved_room`؛ idempotent، بالای لیست پین و با 🔖. ذخیره = فوروارد به همان اتاق.
- **Mute**: `setRoomMutePushRule` + room account data `ir.tikootak.mute_until` برای ۱ ساعت/۸ ساعت/۱ هفته/همیشه؛ علامت 🔕 در لیست، بج خاکستری، و زمان‌دارها بعد از رفرش هم با timer پایان می‌یابند.

### تست‌های انجام‌شده
- ثبت‌نام ch1a و ساخت پشتیبان (room_keys/version=200) بدون هیچ دیالوگ؛ پیام در اتاق رمزنگاری‌شده؛ ورود در context تازه با همان رمز، بدون دیالوگ، پیام‌ها باز شدند.
- گروه عمومی: ch1a ساخت، ch1b از کشف پیدا/عضو شد و پیام قبل از عضویت را دید. کانال: عضو نوار نوشتن نداشت، API ارسال ۴۰۳ داد، ریکشن ۲۰۰ شد، مدیر پست گذاشت. لینک `#/join` با ch1c عضو کرد.
- گروه رمزنگاری‌شدهٔ خصوصی با دو دستگاه تازه: پیام قدیمی برای عضو جدید قفل بود و پیام جدید باز شد.
- DM رمزنگاری‌شده با ch1d/ch1e: درخواست پیام، قبول، و پیام «راز پیوی» در دستگاه مقابل باز شد.
- فوروارد تصویر از گروه به کانال با نشان «فورواردشده از»؛ اتاق ذخیره ساخته/پین شد و پیام ذخیره شد؛ Mute/Unmute و 🔕 لیست کار کرد.
- **تست‌نشده/نامطمئن:** فوروارد ویدیو/ویس به‌صورت جداگانه (مسیر رسانه تصویر تست شد)، نقش‌های گروه (کد پیاده شده)، Muteهای زمان‌دار به‌صورت گذر زمان، و بازشدن پیام‌های قدیمی بعد از تغییر رمز (در تست، پشتیبان تازه بلافاصله کلیدهای قدیمی را نداشت).
